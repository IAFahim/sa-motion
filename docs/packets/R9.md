# R9: Assemble one reaction controller and tune it in the harness

Read `AGENTS.md`, `docs/packets/R-common.md`, `docs/port/R2.md`, `docs/port/R7.md`, `docs/tuning.md`, `docs/harness-scenarios.md`, then this file. They are your whole task. **Start only after R2, R10 and H2 are merged.**

Owns: `src/SA.ReactionControl/Controller/*`, `tests/SA.ReactionControl.Tests/Controller/*`, `docs/port/R9.md`, `docs/handoff/R9.md`, and appended rows in the `Tuning log` of `docs/tuning.md` (append only). Edit nothing else. Parameter value changes go through the `Standard` of the area that owns them: make the smallest change, log it, and list it in your handoff.

## Entry point

```text
static ControllerReport ReactionController.Tick(in ControllerProfile profile, ref ControllerState state, ReadOnlySpan<RoleBody> bodies, ReadOnlySpan<SupportProbe> feet, ReadOnlySpan<SupportProbe> forwardProbes, in ControllerInput input, Span<JointDrive> drives)
```

`ControllerInput`: timestep, an animation target per role (a `Quaternion` relative to the parent, the same convention as `JointDrive.Target`), strength 0 to 1, and a list of get-up clips (`ClipId`, start-pose class, root offset) from R8's types. `ControllerState` holds the state of every sub-controller plus the current mode. `ControllerReport`: owning mode, `ArbitrationReason`, per-role authority actually used, the balance and fall reports.

## Which area writes which role

| Mode | Legs and pelvis (`Pelvis`, `Thigh`, `Shin`, `Foot`) | Torso | Head | Arms and hands |
|---|---|---|---|---|
| Animated | `Drive` toward the animation target | `Drive` | `Drive` | `Drive` |
| Balancing | `BalanceController.Tick` (R2) | R2 spine drive, plus `Drive` toward the animation target blended by `BlendWeights.Authority` | `BodyBalance` head-look if active, else `Drive` | `Drive` toward the animation target at reduced authority |
| Bracing | R2 stance if still upright, else passive | `Brace` spine lean (R5) | `BodyBalance` | `Brace` arm targets (R5) |
| Falling | passive with the authored tone from `BlendWeights` | `BodyBalance` lean (R3) | `BodyBalance` head-look (R3) | `CatchFall` arm response and spin reduction (R4) |
| Recovering | passive, then `Drive` toward the get-up pose when a clip is selected (R8) | same | same | same |

No two controllers write the same role in the same tick except through `BlendWeights.BlendDrive` during a fade (R7's rule: the staying and incoming weights sum to 1). R9 writes that table into code as a data table, not as scattered `if`s.

## Arbitration with R7

R9 builds a `ModeRequest` list from the sub-controllers each tick (balance report `Falling` requests `Falling`; a forward probe hit while falling requests `Bracing`; a rest classification from `GetUp.Classify` requests `Recovering`; strength zero requests `Falling`; otherwise `Balancing` or `Animated` by `ControllerInput`), calls `Coordinator.Arbitrate` with the current mode and `profile.Coordination.HysteresisMargin`, and uses the owner it returns. Never override the arbitration result. Mode changes fade over `Coordination.FadeTime`.

## Tuning procedure

Use the H2 scenarios (`Scenarios.Run` and `Sweep`) against `ReactionController`. Order: (1) standing hold; (2) the 60 N·s sweep; (3) 120 N·s; (4) 200 and 300; (5) 450. Change one parameter at a time, rerun the sweep, log a row. Stop when the thresholds below hold or when two successive changes do not improve the table.

## Pass thresholds (report the measured table whether or not they hold)

1. Stand 10 s: pelvis within 0.12 m, lean within 15 degrees.
2. 60 N·s in all eight directions: `Fell` false, `RecoverySeconds` under 3 s.
3. 120 N·s: at least six of eight directions recover; the others fall without the controller flickering.
4. 450 N·s in all eight directions: `Fell` true and the report says `Falling`.
5. Mode changes: at most one per 0.25 s; exactly one owner per tick.
6. Forward probe in reach while falling forward: `Bracing` is selected and the report says so; nothing in reach: safe-miss arm pose.
7. After a fall: `Recovering`; with no suitable clip the report says "no suitable clip" and the character stays passive.
8. Determinism; hostile inputs give passive drives; no allocation per tick.

Do not weaken a threshold or the harness. If a threshold fails, the handoff says which, the measured value and what you tried.

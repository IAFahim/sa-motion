# L4: Make the leg solver at least twice as fast

Base: branch `packet/L1-legs`. Worktree: `/home/i/GitHub/sa-motion-wt/L4`, branch `packet/L4`.

## Why
`LegRig.Step` (`src/SA.Motion/Legs`) measured 640 ns per leg single-threaded on .NET 10 x64 (10,000 two-leg characters, best of 40 rounds). The target is at most 300 ns per leg, with identical behavior.

## Owns (edit only these)
- `src/SA.Motion/Legs/LegRig.cs`, `Fulcrum.cs`, `SoftReach.cs`, `Planting.cs`
- `src/SA.Motion/Mechanics/CriticalSpring.cs`
- new `tests/SA.Motion.Benchmarks/` (a console project, not added to `SA.Motion.sln`, no new NuGet packages)

## Rules
- Public signatures and every existing test stay unchanged. `tests/SA.Motion.Tests/LegTests.cs` must pass without edits on both library builds. Results stay deterministic (same input, same output) but need not be bit-identical to today.
- The code stays readable, total and comment-free (`AGENTS.md`). No unsafe code, no `System.Runtime.Intrinsics` (netstandard2.1 must compile the same source).
- Ideas, measure each one: `MathF` instead of `Math` with double round trips; skip a spring step when it is at rest on its target; compute `cos(MaxWalkableSlope)` once per `Step`, not once per leg; skip `PoseTransition.Apply` work when the blend has finished; avoid repeated `Quaternion.Normalize` and `Rotate` of the same values; skip slope alignment when the normal equals up.

## Benchmark
`tests/SA.Motion.Benchmarks/Program.cs` reproduces the measured scenario: 10,000 characters, two legs each, a sine-driven step cycle, flat ground, `LegParams.Standard`, 40 rounds, best round reported in ns per leg. Run it with `dotnet run -c Release --project tests/SA.Motion.Benchmarks`. Record the before and after numbers in `docs/handoff/L4.md`.

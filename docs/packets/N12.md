# N12: Hinge axis and range inference from sampled motion

Read `AGENTS.md` first, then this file. They are your whole task.

Owns: `src/SA.Humanoid/Hinge/*`, `tests/SA.Humanoid.Tests/Hinge/*`, `docs/hinge.md`. Edit nothing else. This is independent MIT code: do not read Delirium.

## Why

Knees and elbows are hinges, but a generic rig does not say which local axis they bend about. The ragdoll builder could infer it from an animation: sample a clip, look at how the child rotates relative to the parent, and fit an axis and a range.

## API (namespace `SA.Humanoid.Hinge`)

```text
readonly struct HingeEstimate { Float3 Axis; float Min; float Max; float Fit; bool Valid }
static class HingeInference { HingeEstimate Estimate(Quaternion rest, ReadOnlySpan<Quaternion> relativeSamples) }
```

`relativeSamples` are child-in-parent rotations. `Axis` is a unit vector in the parent-local frame, `Min` and `Max` are the angles in radians about that axis relative to `rest` (shortest-arc, `Min <= Max`), `Fit` in 0..1 is how much of the rotation energy lies about that axis (1 is a perfect hinge). `Valid` is false when there are too few samples, the motion is under 0.05 rad, or `Fit` is below 0.8.

## Check

- Synthetic hinge about each of x, y, z and an oblique axis, with a known range: axis (up to sign) and range recovered within 0.02 rad.
- A ball-like motion (rotation about two axes) gives low `Fit` and `Valid` false.
- Samples are sign-flipped quaternions (q and -q mixed): same answer.
- Constant samples, a single sample, NaN and infinity: `Valid` false, finite fields, no exception.
- Deterministic; no allocation beyond locals.

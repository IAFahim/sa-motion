## API

```text
readonly struct ControllerProfile { string Name; BalanceParams Balance; BodyBalanceParams BodyBalance; CatchFallParams CatchFall; BraceParams Brace; DriveParams Drive; CoordinationParams Coordination; GetUpParams GetUp; }
static class ControllerProfiles {
  ControllerProfile Standard { get; }
  ControllerProfile ForBody(float totalMass, float height)
  string[] Validate(in ControllerProfile profile)
  ControllerProfile Sanitize(in ControllerProfile profile)
}
```

(Use the real type names found under each area.) R2 will add its own state types; it does not add parameters, so the profile does not wait for it.

- `Validate` returns one string per problem: `Area.Field: reason`. A problem is a non-finite value, a value outside the documented range, or a zero where zero silently disables a behavior. Empty array means valid.
- `Sanitize` replaces every offending value with its `Standard` value. Total, never throws, no allocation when the profile is already valid.
- `ForBody` scales what depends on body size: torque caps, stiffness and strengths with mass; lengths, reach and step sizes with height. The rule for every scaled field is written in `docs/tuning.md`. Dimensionless fields do not scale.

## Table and citation rule (same discipline as N5)

`docs/tuning.md` has one row per parameter: `Area | Field | Unit | Range | Value | Source | Exercised`. `Source` is one of:

- `P: <author, year, table>`: a published value, only if you can name the exact table;
- `S: <slot>`: the numeric slot in the original code gave the meaning, the value is authored (give the slot number from the port record);
- `A: <reason>`: an authored starting value with a one-line reason.

No value may claim `P` without a named table. `Exercised` is `harness <scenario>` if a harness run has used it, otherwise `no`. Most are `no`: say so, do not guess. Under 200 lines plus the log.

## Tuning log

At the end of `docs/tuning.md`, a section `Tuning log` with this table header and one example row marked as an example: `Date | Scenario | Area.Field | Before | After | Measured effect | Who`. Rule: any change to a `Standard` value must add a row. A test checks that every field in the profile appears in the table and that the log header exists.

## Check

- Every public field of every area `Params` appears in the table (a test walks them by reflection; reflection in tests is allowed).
- `Standard` validates clean. Profiles with NaN, infinity, negative gains and out-of-range values are reported by `Validate` and repaired by `Sanitize`.
- `ForBody(70, 1.75)` equals `Standard` within 1e-6; doubling the mass doubles torque caps and leaves dimensionless fields alone; halving the height halves lengths.
- Deterministic. No allocation in `Sanitize` on a valid profile and in `ForBody`.

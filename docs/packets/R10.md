# R10: Independent controller parameter profile and tuning log

Read `AGENTS.md` first, then `docs/packets/R-common.md`, then this file. They are your whole task.

Owns: `src/SA.ReactionControl/Profile/*`, `tests/SA.ReactionControl.Tests/Profile/*`, `docs/tuning.md`. Edit nothing else. Read every `docs/port/R*.md` slot map and every `<Area>Params.Standard` already merged (`Balance`, `BodyBalance`, `CatchFall`, `Brace`, `Drive`, `Coordination`, `GetUp`).

## Deliver

- `ControllerProfile`: one readonly struct that holds every area's `Params` plus a `Name`, with `ControllerProfile.Standard` built from each area's `Standard`.
- `ControllerProfile.Validate(profile)` returns a list of problems: any non-finite value, any value outside the range you document, any field left at zero where zero disables the behavior. `ControllerProfile.Sanitize(profile)` returns a profile with every offending value replaced by its `Standard` value (total: never throws).
- Scaling: `ControllerProfile.ForBody(float totalMass, float height)` scales the gains, torque caps and lengths that depend on body size, with the rule for each field written in `docs/tuning.md`.
- `docs/tuning.md`: a table with one row per parameter: area, field, unit, documented range, authored value, source slot or reason, and whether it was ever exercised by a solver run (most were not: say so). Keep a "Tuning log" section for future entries with date, scenario, change and measured effect. Under 150 lines.

## Check

- Every public field of every area's `Params` appears in the table, verified by a test that walks the fields by reflection in the test project (reflection in tests is allowed).
- `Standard` validates clean. A profile with NaN, infinity, negative gains or out-of-range values is reported by `Validate` and repaired by `Sanitize`.
- `ForBody(70, 1.75)` equals `Standard` within 1e-6; doubling the mass doubles torque caps and leaves dimensionless fields alone.
- Deterministic, no allocation in `Sanitize` and `ForBody`.

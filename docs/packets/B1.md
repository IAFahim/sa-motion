# B1: Independent standing and push-recovery controller (capture point)

Read `AGENTS.md`, `docs/harness.md`, `docs/harness-scenarios.md`, `docs/contract.md` (the `JointDrive.Target` world-frame rule), then this file. They are your whole task. This is independent MIT code: **do not read Delirium or `src/SA.ReactionControl`**. Derive it from published control theory: the linear inverted pendulum and capture point (Pratt et al. 2006; Koolen et al. 2012), ankle and hip strategies (Kuo and Zajac 1993), and ordinary joint-space PD with gravity compensation.

## Why

The port-based controller (R2, R2b) has not stood in the harness after 35 experiments. The harness already proves a strong static pose hold stands for 5 s (`docs/harness.md`). A standard controller built in stages should stand first and then earn pushes.

## API

The library does not reference the GPL project, so it defines its own plain structs; a test adapter converts to and from `RoleBody` and `JointDrive`.

```text
struct BodyState { Float3 Position; Quaternion Rotation; Float3 LinearVelocity; Float3 AngularVelocity; float InverseMass; }
struct FootContact { bool Hit; Float3 Point; Float3 Normal; }
struct BodyDrive { Quaternion TargetWorld; float Stiffness; float Damping; float MaxTorque; }
struct BalanceInput { float Timestep; Quaternion[] / ReadOnlySpan<Quaternion> TargetWorld per role; }
struct BalanceReport { Decision Decision (Standing, Recovering, Stepping, Falling); Float3 Com; Float3 CapturePoint; float Margin; int SteppingFoot; }
static class StandingController { BalanceReport Tick(in BalanceParams p, ref BalanceState state, ReadOnlySpan<BodyState> bodies, ReadOnlySpan<FootContact> feet, in BalanceInput input, Span<BodyDrive> drives) }
```

Bodies and drives are indexed by `(int)Role` (15 entries). `BalanceParams.Standard` holds every number with a name and a one-line reason in `docs/balance.md`. `TargetWorld` is the animation pose to hold, as world orientations (see `docs/contract.md`).

## Stages (commit after each; each must pass its scenarios before the next)

Use H2 (`tests/SA.Harness/Scenarios`) at 60 Hz.

1. **Hold.** Gain-scheduled strong pose hold on every joint (use the schedule in `docs/harness.md`), pelvis height servo. Target: stand 10 s, pelvis within 0.08 m of start, torso within 10 degrees.
2. **Ankle and hip strategy.** Use the capture point to shift the COP and lean the pelvis and torso against a push. Target: 60 N·s in all eight directions, `Fell` false, `RecoverySeconds` under 3 s.
3. **Stepping.** When the capture point leaves the support polygon plus a margin, place the swing foot at the capture point plus a margin through leg IK, lift, land, and replant. Target: at 150 N·s at least four of eight directions recover with at least one step; report the table for 60, 100, 150, 200, 300 N·s.
4. **Failure.** When the capture point is unreachable (beyond leg reach and step time), latch `Falling`, release stiffness to a low tone and stop commanding steps. Target: 450 N·s in all eight directions: `Fell` true, report `Falling` and stays so.

## Always

Total functions (hostile input gives passive drives and a finite report), deterministic (two runs bit-identical), no allocation per tick, no comments. Run `eng/dotnet_test.sh tests/SA.Balance.Tests/SA.Balance.Tests.csproj` and `python3 eng/check_source_rules.py` before every commit.

## Stop rule

At most **40 logged experiments** in total, one line each in `docs/handoff/B1.md` (change, scenario, before, after). Stop at the end of stage 4 or when the experiments run out. A stage that did not pass is reported with its measured table, never loosened. The deliverable is the sweep table from H2 for stages that passed.

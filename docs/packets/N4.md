readonly struct SkeletonBone { string Name; int Parent; SA.Motion.Numerics.Pose Rest }     Parent -1 means root

## Rules

- `Map` validates an explicit map (from an Avatar or an author). It never guesses. Checks: map length, indices in range, every role mapped, no bone used by two roles, parent indices valid, no parent cycle, and each role's bone is a proper descendant of its parent role's bone (intermediate spine or clavicle bones are allowed).
- `Suggest` proposes a map from names, case-insensitive, ignoring separators and common prefixes: hips/pelvis, spine/chest/torso (the highest spine-like bone below the head chain), head, shoulder-versus-arm tokens, forearm/lowerarm, hand, thigh/upleg/upperleg, shin/calf/lowerleg/leg, foot, with left/right from `left`, `right`, `_l`, `_r`, `.l`, `.r`, `L_`, `R_`. Unfound roles are -1. The result is a suggestion; callers must pass it through `Map`.
- Diagnostics are ordered by role then code, so repeated calls give identical results. Never throw on bad data.
- Out of scope, do not attempt: left/right geometry checks, forward/up detection, T-pose or A-pose detection.

## Tests

- A Mixamo-style skeleton (Hips, Spine, Spine1, Spine2, Neck, Head, LeftShoulder, LeftArm, LeftForeArm, LeftHand, the same on the right, LeftUpLeg, LeftLeg, LeftFoot, LeftToeBase, and the right side) and a differently named and differently ordered generic skeleton (for example `pelvis_jnt`, `spine_01`, `l_upperarm`) both go through `Suggest` then `Map` with `IsValid` true.
- Failure cases each produce the expected code and role: missing leg, a bone used twice, a cycle, an out-of-range parent, a forearm placed outside its upper arm's subtree, wrong map length, out-of-range map index.
- Repeated calls give equal results.

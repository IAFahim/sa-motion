# Port record R10: controller parameter profile

No upstream ranges were read for this packet. All values below are the
`Standard` sets already merged under `src/SA.ReactionControl/<Area>/`, with
per-field provenance in `docs/tuning.md`. Ordinary float math throughout.

## Function map

| C# member | Inputs (units, basis) | Outputs (units, basis) | Notes |
|---|---|---|---|
| `ControllerProfile` | `Name` label plus the seven area `Params` structs | one tunable snapshot for the whole controller | plain struct, sequential layout, no behavior |
| `ControllerProfiles.Standard` | none | profile with every area at its `Standard` | reference body is 70 kg, 1.75 m |
| `ControllerProfiles.ForBody` | `totalMass` kg, `height` m | profile scaled to that body | mass factor scales torque caps, stiffness and strengths; height factor scales lengths, reach and step sizes; dimensionless fields keep their values; non-positive or non-finite input gives `Standard` |
| `ControllerProfiles.Validate` | profile | one `Area.Field: reason` string per problem | a problem is a non-finite value, a value outside the documented range, or a zero where zero silently disables a behavior; empty array means valid |
| `ControllerProfiles.Sanitize` | profile | profile with every offending value replaced by its `Standard` value | total, never throws; no allocation when the profile is already valid |

## Slot map

`docs/tuning.md` is the slot map: one row per field with unit, range, value,
source and harness use. Source is `S:<site>` where the cited port record ties
the field to original code (kv slot or use-site line), otherwise `A:<reason>`
for an authored value. No value claims a published table. The body-scaling rule
for every scaled field is written in `docs/tuning.md` next to its unit.

## Excluded and adapted

- No area `Params` or `Standard` is changed here. Values that look wrong are
  listed in the handoff, never edited.
- `Validate` allocates by contract: it returns a string per problem. The
  no-allocation rule still holds for `Sanitize` on a valid profile and for
  `ForBody`, which reuse the `Standard` name reference and build the result
  from stack-local struct copies only.
- The 21-part to 15-role collapse does not apply: the profile carries tuning
  only and never indexes bodies by role.
- R2 owns the mode switch and its own state types; the carried R1 fields
  (`AbortThreshold`, `Taper`, `LowAbort`, `ContactResponse`, `LegStiffness`)
  keep the values R1 merged. `Name` is a label and is never validated or
  replaced.
- Fields present in merged code but missing from their area slot map keep
  authored `A` sources in `docs/tuning.md`; the gaps are listed in the handoff
  as suspects for the owning packets, not silently renamed.

## Unresolved

- `docs/port/R3.md` records `DecisionLoseLean` 0.45 and `DecisionFallLean` 0.9
  but merged `BodyBalanceParams.Standard` carries 0.12 and 0.6. The code is
  authoritative here; the owning packet confirms which record is stale.
- Absolute stiffness scales were never tuned against a solver; every torque
  cap and stiffness keeps its authored starting value.

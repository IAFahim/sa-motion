# Port record R8: get-up selection and root alignment

Source: Delirium Physics at revision `8e4ad4e`
(`https://github.com/PVCPC/delirium-physics`, GPL-3.0-only, see `docs/provenance.md`).

Ranges read:

- `crates/delirium-room/src/getup.rs`, all 468 lines
  (`Clips::load`, `pose`, `play`, `play_fight`, `bend`, `point_bone`,
  `place`, `start`, `stand`, `frames`, `standing`, `end`).
- `crates/delirium/src/ragdoll.rs` lines 3076-3086 (`Rig::rise`).
- `crates/delirium-room/src/main.rs` lines 1298-1397 (`rise`, `rise_sides`)
  and line 1344 (lying branch), plus `crates/delirium-room/src/gamenums.rs`
  lines 32, 38 (`LYING_HEAD`, `FATAL`).

Arithmetic: ordinary float math throughout. No console-arithmetic emulation
(`fma` ordering, `frsqrte`, `vrefp`, bit-exact estimates). No game numbers
copied: every threshold below is authored and recorded in the slot map.

Basis: world `+Y` up in metres, yaw about `+Y` as `atan2(x, z)`. The source
world is `+Z` up and takes the skeleton-local `+Y` axis as the yaw reference
(`getup.rs:423`, `ragdoll.rs:3079`). The port uses the pelvis-local `+Z` axis
as forward projected onto the ground (`XZ`) plane, which is the Unity
convention the product solver uses. Ground plane is `Y = 0`; the caller adds
terrain height.

Engine types never cross the boundary. `Vec3`/`Quat` become
`SA.Motion.Numerics.Float3`/`Quaternion`; `Transform` pairs become
`RoleBody` snapshots in, plain result structs out. No `Character`, `Ragdoll`,
`Collision`, `Obstacle`, `Ctx`, clip data, or callbacks.

## Part collapse (21 source parts onto 15 roles)

Source `build.parts` has 21 parts: pelvis root, four spine segments, neck,
clavicles, head, and limb segments. `chest` (`getup.rs:251`) is the first
non-lower child of part 0, i.e. the lowest spine segment. The port collapses:

| Source parts | Role |
|---|---|
| pelvis root (part 0) | `Pelvis` (root index for alignment; `lay[0]` in `start`) |
| all four spine segments, neck, clavicles | `Torso` (chest reference for classification) |
| head part (`HEAD = 12` in `main.rs:62` frames) | `Head` (lying-test endpoint) |
| upper arm / forearm / hand, thigh / shin / foot, left and right | matching `Role` one to one |

Limbs are unused by selection and alignment beyond the three reference roles;
they stay in the span so later packets can reuse the snapshot.

## Unresolved / opaque fields

None kept. Every ported threshold is behaviour-named above. The opaque game
tuning (`kv!` values, `DOWN_SECS` still-time, clip-bank indices) was excluded,
not renamed, with reasons in the slot map. There is no `no suitable clip`
signal in the source (it `expect`s a clip); the explicit
`HasClip = 0, ClipId = -1` result is original behaviour required by the packet
because this project ships no game animations and must never invent one.

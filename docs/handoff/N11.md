# N11 handoff: ragdoll layout from a mapped skeleton

## What was built

`src/SA.Humanoid/Build/` (new, only files added by this packet):

- `Layouts.cs`: `BodyLayout`, `JointLayout`, `RagdollLayout` with the exact
  packet API. `Bodies` has `Roles.Count` entries indexed by role; `Joints`
  has `Roles.Count - 1` entries ordered by child role. Sequential readonly
  structs, block-scoped `SA.Humanoid.Build`, C# 9, null inputs coalesced.
- `BuildParams.cs`: `RadiusFor` per limb class plus `IsBox` (pelvis, torso)
  and box width/depth selectors. `Standard` holds eight named authored
  ratios (limb 0.12, head 0.28, hand 0.16, foot 0.16, pelvis width 0.80 /
  depth 0.50, torso width 0.40 / depth 0.28).
- `BuildDiagnostics.cs`: build-local codes reusing the N4 `Diagnostic`
  struct: 7 `ZeroLengthSegment`, 8 `BadBoneScale`, 9 `BadRestValue`,
  10 `BadTotalMass`.
- `RagdollBuilder.cs`: validates the map with `HumanoidMapping.Map` and
  keeps its diagnostics, composes world rest poses with guarded walks
  (out-of-range parents stop, cycles stop by step bound), rejects
  non-uniform/non-positive/non-finite scales at 1e-4 relative tolerance,
  builds body frames at role joints with x toward the next role joint
  (preferred: torso for pelvis, head for torso, distal neighbour down each
  limb; leafs continue the parent direction; fallbacks longest viable
  child, reversed parent, +X), fits capsules joint to joint and boxes
  mid-segment, takes masses and limits from `HumanProfile`, anchors each
  joint in both body frames, stores child-side joint frame identity and
  parent-side `RestRelative = inverse(parent) * child`. Total: every bad
  input yields diagnostics with `IsValid` false and finite outputs, never
  an exception. Only plain arrays are allocated.

`tests/SA.Humanoid.Tests/Build/` (new): `RagdollFixtures.cs` (20-bone Kyle
skeleton with neck, shoulders and toes as unmapped intermediates, rotated
generic variant, mirrored variant, map, helpers), `RagdollBuilderTests.cs`
(12 facts: Kyle and rotated-generic valid, masses sum, anchors coincide,
limits equal profile, finite, joint-frame convention, Standard ratios,
endpoints and box centres on segments, mirror, root uniform scale doubling,
determinism), `RagdollBuilderFailureTests.cs` (zero-length, 2 mm threshold,
missing role, non-uniform, non-positive, non-finite rest, bad mass theory,
null, all-unmapped, diagnostic ordering).

`docs/build.md` (new): API, frame/segment rules, authored ratios, scale and
totality behavior, diagnostic codes, mirror note. No Delirium, Unity, GTA,
`kv.bin` or tuning content anywhere. Touched nothing outside the packet
paths. `SA.Humanoid.csproj` and the test project are unchanged.

## Commands run with real output

`eng/dotnet_test.sh tests/SA.Humanoid.Tests/SA.Humanoid.Tests.csproj` ->
`Passed! - Failed: 0, Passed: 56, Skipped: 0, Total: 56`
(SA.Humanoid.Tests.dll, net10.0, Release).
`python3 eng/check_source_rules.py` -> `source rules: ok`.

Two test-side mistakes were found and fixed before green: the radii test
derived box extents circularly from zeroed capsule fields (now uses
independent fixture segment lengths) and the uniform-scale test scaled every
bone, which compounds hierarchically by design (now scales the root only,
which doubles every segment exactly).

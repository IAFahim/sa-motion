- Groups: ScalarDecay (Create+Evaluate, hostile struct Evaluate), VectorOffset (Create+Apply, hostile struct Apply, extra finite-destination check), RotationOffset (Create+Apply, hostile struct Apply, extra finite-destination check), PoseHistory (Reset+Capture), PoseTransition (Create+Apply, extra finite positive-scale destination check), Quaternion (Normalize, Canonical, AxisAngle, Multiply, InverseUnit).
- Each Fact asserts no exception, finite outputs when all read inputs are finite, and for Apply finite output when destination is finite (positive-scale for Pose). First violation records exact inputs and fails once at the end, keeping the loop fast.
- Two genuine kernel gaps found, marked `[Fact(Skip)]`, main stays green. No `src/` edits.

## Gap reproductions
### OPEN GAP 1: VectorOffset.Apply
- Skipped test: `TotalityTests.VectorOffsetTotality` with `Skip = "OPEN GAP: VectorOffset.Apply finite destination with hostile offset gives non-finite output"`.
- Exact input: `Direction=(-0, NaN, +Inf)`, `Decay=(Duration=-Inf, C0=1E-45, C1=3.4028235E+38, C2=-3.4028235E+38, C3=1E-30, C4=-1E-30, C5=1E+30)`, `destination=(3.4028235E+38, -3.4028235E+38, 1E-30)` (all finite), `elapsed=-1E+30` (finite).
- Actual output: `(3.4028235E+38, NaN, NaN)` (non-finite).
- Expected output: all components finite whenever destination is finite.
- Root cause: `VectorOffset.Apply` computes `destination + Direction * Decay.Evaluate(elapsed).Value` with no guard on hostile `Direction` or `Decay` fields.

### OPEN GAP 2: Quaternion.Multiply
- Skipped test: `TotalityTests.QuaternionTotality` with `Skip = "OPEN GAP: Quaternion.Multiply finite inputs overflow to Infinity"`.
- Exact input: `a=(-0, 3.4028235E+38, -1E-30, 5.4953027)` (all finite), `b=(6.546166, -5.3945255, -0, 3.4028235E+38)` (all finite).
- Actual output: `(35.973164, +Inf, -Inf, +Inf)` (non-finite).
- Expected output: all components finite whenever both inputs are finite.
- Root cause: `Quaternion.Multiply` sums products like `a.W * b.Vector` without overflow clamping; `MaxValue * ordinary` overflows to `Inf`.

## What was not verified
- Unity paths (`eng/unity.sh`) were not run; pure `src/` packet only.
- Exhaustive Cartesian product of the 24-entry palette was not run; 200000 pseudo-cross combinations per Fact via coprime strides were run, which cover the full 24^2 and 24^3 spaces many times over but do not hit every high-arity tuple.
- `PoseTransition.Apply` with a directly hostile `PoseTransition` struct (arbitrary `LogScale` fields) was not fuzzed; only `Create`-derived transitions were checked for the extra finite-destination property. The `VectorOffset` gap implies hostile `LogScale` would also fail, same root cause.
- Performance was measured only via `dotnet test` Duration (170 ms for the whole suite, 176 ms with all 6 Totality Facts running); no separate per-class profiler was run.

## Open questions and ambiguity notes
- Simplest reading used: every float field read by the function is drawn from the palette, including struct fields for `Evaluate` and `Apply` hostile cases.
- For `VectorOffset.Apply` the destination is `Float3`, so positive-scale has no meaning; the extra check was implemented as destination finite implies output finite. For `RotationOffset.Apply` the destination is `Quaternion`, same finite-only reading. For `PoseTransition.Apply` the extra check was implemented as destination finite and `Scale.IsPositive` implies output finite.
- `ScalarDecay.Evaluate` hostile finite inputs passed for the sampled 200000 combos; a different stride could stack same-sign `MaxValue` coefficients with `t` near 1 and overflow, but no such combo was hit in this run. This is noted, not claimed as proof of totality.

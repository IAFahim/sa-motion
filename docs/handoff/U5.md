# U5: automatic setup, locomotion and IK

Worked directly in both canonical checkouts on `packet/U5-simple-setup`, without agents. Companion SA package: `/home/i/ruk2/Packages/com.sa.unity`, commit `fdc77bc` on the same branch. No Rukhanka package changes.

## Result

Select a character and run `Tools/SA/Set Up Character`, then drop models, controllers, clips or folders into **Animation packs**. Bone/Avatar discovery, conversion and all material slots are automatic. Imported assets remain intact. The main Inspector exposes the starting animation, in-place, smooth transitions and foot planting; overrides remain under Advanced. `Tools/SA/Set Up Ragdoll` adds the automatic physical character setup.

Per-clip aliases live in the rig's small clip-reference table. They do not duplicate sampled data. Same-named clips from separate sources receive qualified names. Clip cache keys include in-place/motion-bone settings, and the in-memory clip key no longer changes merely because Unity lazily populates its editor curve cache.

The skin baker binds every actual render entity, including Entities Graphics' additional material entities. Live UAL inspection found two bound skin render entities per character. UAL1 used 86 discovered clips from UAL1/UAL2, zero manual clips and zero ExtraBones. A baked UAL2 walk on the UAL1 target had 41 frames and 74.15 degrees of animated bone rotation. The live mannequin rendered and animated, including its moving reach target; capture: `artifacts/U5/mannequin.png` locally.

In-place baking removes horizontal model-space travel, with automatic pelvis/root selection or an explicit motion bone. It preserves vertical motion and limb-local curves. It does not extract gameplay root motion.

## Kyle's Run to Sprint

The demo was cutting the next looping clip to phase zero. `TransitionPlayback.PlaySynced` now carries the outgoing gait phase into the new clip, without restarting repeated requests. Ordinary `Play` retains phase-zero action semantics.

Live frame recording found another artifact in the new foot adapter: releasing a planted foot discarded the entire IK correction at once. Both acquisition and release now blend over 0.1 seconds, with the previous world/support anchor retained during release. The maximum leg rotation step in the checked sprint window fell from about 50 degrees to 25.5 at roughly 60 Hz; the latter is dominated by the source animation's approximately 24.8-degree ankle step. The switch frame itself remained continuous. These are visual-correctness measurements, not performance results.

Local diagnostic files are `artifacts/U5/gait-raw.csv` and `gait-smooth.csv`. The temporary `U5GaitProbe` project script was removed after measuring. Regression coverage checks phase retention/repeated calls, gradual foot correction, retained release anchors, planted-foot position, moving supports and physics ownership.

## Package boundaries

- `SA.Motion.Kinematics`: pure two-bone reach, limited aim and foot-contact state/blending. No Unity dependency or per-call allocation.
- `com.sa.unity`: authoring/discovery/baking, in-place, per-character clip names, phase-preserving playback and the external-pose ownership tag.
- `com.sa.unity.ik`: optional ECS head look-at and two-bone limb targets, with automatic Humanoid/standard-name mapping. Targets can move every frame. It also computes desired poses for physical controllers without teleporting simulated bones.
- `com.sa.unity.reactions`: Unity Physics ground queries, foot/support locking, automatic ragdoll setup and layer-2 hit flinches. Flinch defaults to a discovered hit animation with an automatic UpperBody mask; explicit overrides remain available.

Unity adapters stay in packages because they read entities, hierarchy transforms or PhysicsWorld and schedule Burst jobs. Portable solver math stays in `src/`. DLL artifacts were repacked through the existing scripts.

## Limits

- Generic clips still need compatible skeleton bindings. UAL cross-pack Humanoid sampling was verified; arbitrary Generic-to-Humanoid or cross-skeleton retargeting was not implemented.
- Foot IK assumes Y-up, ground collision layer 1 and automatically calibrated sole height. It is optional, requires Reactions/Unity Physics and uses CPU bones. Universal no-slip behavior, uneven terrain and broader artistic controls are not claimed.
- Head look and two-bone reach are implemented; full FABRIK/sample parity is not claimed.
- Inertial transitions remain CPU-only. GPU inertialization and performance at crowd scale were not measured here.
- Balance/stepping remains off by default and is still not working in Unity Physics. No new balance or GTA behavior claim is made.
- The UAL physical thresholds were not retuned or weakened; the earlier Kyle-specific head-deflection failure is not declared fixed.

Use both packet branches together. The integrator merges them; neither branch is pushed onto main.

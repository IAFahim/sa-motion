Signatures. Commands take `Span<ClipState> states, ref int count` where Unity took `ref DynamicBuffer<ClipState>`.

```
Playback.Play(states, ref count, ClipIndex clip, in PlayOptions options)
Playback.CrossFade(states, ref count, clip, float seconds, in options)
Playback.Blend(states, ref count, ReadOnlySpan<ClipIndex> clips, ReadOnlySpan<float> weights, float seconds, in options)
Playback.Stop(states, ref count, byte layer, float seconds)
Playback.Find / IsPlaying / NormalizedTime / HasFinished(ReadOnlySpan<ClipState> states, int count, byte layer, ClipIndex clip)
Playback.Seek(Span<ClipState> states, int count, byte layer, ClipIndex clip, float phase)
Playback.Rate(ReadOnlySpan<float> durations, in ClipState state)
Playback.SyncedRate(durations, ReadOnlySpan<ClipState> states, int count, byte layer)
Playback.Step(states, ref count, ReadOnlySpan<float> durations, float deltaTime)
TransitionPlayback.Play / PlaySynced(states, ref count, ref TransitionIntent intent, uint key, ClipIndex clip, float seconds, in options)
TransitionPlayback.Blend(states, ref count, ref intent, uint key, clips, weights, float seconds, in options)
TransitionPlayback.Membership(ReadOnlySpan<ClipIndex> clips, in PlayOptions options)
```

Judgment calls, each one a place where the packet left room:

- `TransitionIntent.Pending` is a `byte`, 0 or 1, not a `bool`. `ClipState.Synced` and `RequestState.Active` are bytes for the same reason. `Marshal.SizeOf<TransitionIntent>()` is 28, which is the size the Unity component has by its field order (a 16-byte `RequestState`, two floats and a flag byte); a test checks the size and offsets, but I did not measure the Unity struct.
- The capacity is `min(states.Length, Playback.MaxStates)` with `MaxStates = 1024`, not `states.Length`. The small flag array `Converge` needs stays on the stack for any span length. Spans up to 1024 behave exactly as the packet says. `count` is clamped into `[0, capacity]` and written back.
- Full buffer: the new state goes into the slot of the replaced state, so the order of the rest is kept. A state the same command already placed or reused is never replaced, and if nothing can be replaced the clip is skipped. A `Weight * Fade` that is not finite counts as 0. This is in `docs/animation.md`.
- `Step` has no scratch array for the rates. It advances every phase first and then the fades. The synced rate never reads the phase, so the result equals Unity's.
- Slots past the count are cleared after a removal, so two spans with equal live parts are equal as a whole.
- Hardening beyond Unity, all for inputs that Unity does not guard: a fade time so small that `1 / seconds` overflows gives a fade rate of `float.MaxValue` (it was infinity, and infinity times a zero step is NaN); merged weights saturate at `float.MaxValue`; `Rate` and `SyncedRate` return finite values; a NaN fade counts as 0; `PlaySynced` copies a finite phase only.
- `Membership` is on `TransitionPlayback` (Unity has it on `Inertial`). The formula is unchanged and the golden values in the test were computed separately in Python.
- `Playback.Finite` was not ported. Nothing in the packet's list needs it, and `Scalar.Finite` exists. `Playback.Live` is `internal` so `TransitionPlayback` shares the clamp.

## What the tests are worth

`PlaybackParityTests` holds a line-for-line transcription of the Unity `Playback` and `TransitionPlayback` over a `List<ClipState>`. It replays 3000 random commands on each of 8 seeds, then 4 more seeds with NaN and infinite seconds, weights, speeds and steps. After every command it requires identical states bit for bit, identical intents, and identical results from every query, while the buffer never fills. Every seed sees all three transition decisions.

To check that the suite can fail, I applied 54 distinct one-line bugs to the two library files, one at a time with a throwaway script (not committed), and restored each from git. Examples: `Pick` ignoring a restart, the wrong eviction tie, no group phase, a missing tail clear, an unclamped count, an allocation in `CrossFade`, a changed hash constant. Result: 53 were caught. Three were caught only after I added tests (NaN seconds acting like zero, a steady state counting as playing, a NaN phase not copied). The one that still passes is an equivalent mutant: `keep[i] ||` in `Pick` never changes the result, because a state kept by a command always has a fade rate of 0 or more. It stays as Unity wrote it. The first batch ran against the 66-test suite and the second against the 71-test suite; only the survivors were re-run against the final suite.

## Not verified

- The Unity Editor was not run (the packet forbids it). The parity is against a transcription of the Unity code in the test file, with `Unity.Mathematics` replaced by `System.Math`, not against Unity executing it.
- Nothing was timed. The allocation test shows 0 managed bytes on the test thread over 500 command and step cycles on the .NET 10 runtime. It says nothing about IL2CPP or Mono.
- Only `SA.Animation.Tests` was run, as the packet asks. No other test project was run.
- `docs/index.md` was not updated, because the packet forbids editing files it does not own. Add a line for `docs/animation.md` when merging.

## Open questions

- `MaxStates = 1024` is my number. Raise it if any rig needs more simultaneous states; the only cost is stack space for one flag per slot.
- `SyncedRate` takes `count` because a span plus a count is the buffer model here. Unity's version took an already sliced span; a caller that slices can pass `states.Length` as the count.

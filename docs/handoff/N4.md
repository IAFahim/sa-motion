# N4 handoff: humanoid role mapping

## What was built

`src/SA.Humanoid/Mapping/` (new, only files added by this packet):

- `Types.cs`: `SkeletonBone` (name, parent index with -1 for root, rest `Pose`),
  `DiagnosticCode` (7 codes in packet order), `Diagnostic` (code, role, bone),
  `MappingReport` (`BoneOfRole` with `Roles.Count` entries and -1 for unmapped,
  `Diagnostics`, `IsValid`). All `StructLayout.Sequential` readonly structs,
  block-scoped namespace `SA.Humanoid.Mapping`, C# 9, null inputs coalesced so
  every entry point is total.
- `HumanoidMapping.Map.cs`: validates an explicit map and never guesses.
  Wrong-length (null or not `Roles.Count`) short-circuits to `BoneOfRole` all -1
  plus one `WrongMapLength` diagnostic on `Role.Pelvis`. Otherwise per role:
  -1 gives `RoleMissing`, any other out-of-range index gives
  `MapIndexOutOfRange`; a bone claimed by an earlier role gives
  `BoneUsedByTwoRoles` on the later role; the bone ancestry walk gives
  `ParentIndexOutOfRange` or `ParentCycle`; each non-root role whose bone is not
  a proper descendant of its parent-role bone gives
  `RoleNotBelowItsParentRole` (intermediate spine, neck, shoulder and clavicle
  bones pass through fine). A double-used bone also fails the descendant check,
  so that role gets both codes. Descendant checks are skipped when either
  chain is already bad, keeping those diagnostics single. Diagnostics are
  insertion-sorted by role then code, so repeated calls are identical.
  `IsValid` is true exactly when there are no diagnostics.
- `HumanoidMapping.Suggest.cs`: name-based proposal, case-insensitive with
  separators (`_ - . space : / \ |`) removed before substring matching, so
  prefixed names such as `mixamorig:Hips` still match. Side comes from `left` /
  `right` substrings, else from a separator-delimited `l` / `r` token, covering
  `_l _r .l .r L_ R_`. Pelvis matches `pelvis` / `hips`; torso matches `spine` /
  `chest` / `torso` and picks the deepest spine-like ancestor of the chosen
  head bone (falling back to the deepest spine-like center bone when no head
  chain exists); head matches `head`; upper arm matches `arm` without `fore`
  and falls back to `shoulder` only when no arm token exists on that side;
  forearm matches `fore`+`arm` / `lower`+`arm`; hand matches `hand`; thigh
  matches `thigh` / `upperleg` / `upleg`; shin matches `shin` / `calf` /
  `lowerleg` / bare `leg` excluding thigh tokens; foot matches `foot`.
  Center roles only use side-neutral bones, lateral roles only same-side bones,
  shallowest match wins with lowest index as tie-break. Unfound roles are -1.

`tests/SA.Humanoid.Tests/Mapping/` (new):

- `MappingTests.cs`: a 22-bone Mixamo-style skeleton and a 17-bone
  differently named, differently ordered generic skeleton
  (`pelvis_jnt`, `spine_01`, `l_upperarm`, `calf.l`, `L_foot`, `upleg_R`,
  `shin_R`, `foot_R`, ...) both go through `Suggest` with exact expected maps
  and then `Map` with `IsValid` true; repeated `Suggest` / `Map` calls give
  equal results; null and empty inputs stay total (`Suggest` all -1, null map
  invalid, all-unmapped map yields 15 `RoleMissing`).
- `MappingFailureTests.cs`: one fact per failure case (missing leg, bone used
  twice, cycle, out-of-range parent, forearm outside its upper-arm subtree,
  wrong map length, out-of-range map index), each asserting the expected code
  and role; plus ordering assertions (role then code) and the documented
  double-use plus descendant double diagnostic in code order.

Touched nothing else: `SA.Humanoid.csproj`, `Roles.cs` and the test project
are unchanged. No Delirium, Unity, GTA, `kv.bin` or tuning content anywhere.

## Open questions and judgment calls

- `shoulder`-versus-`arm`: the packet lists upper-arm matching as
  shoulder-versus-arm tokens. `Suggest` prefers an `arm` token and uses
  `shoulder` only when no same-side `arm` bone exists, so Mixamo clavicles
  (`LeftShoulder`) are never picked as upper arms while shoulder-only rigs
  still get a suggestion. If shoulder should never be an upper-arm fallback,
  delete the fallback branch and its (currently untested) path.
- `WrongMapLength` is attributed to `Role.Pelvis` with bone -1 so the
  diagnostic keeps the required shape; the packet does not name a role for
  this case.
- For parent-structure failures the diagnostic `Bone` is the role's own
  mapped bone rather than the offending parent index.
- `wrist`, `clavicle`, `collar`, `elbow`, `knee`, `ankle` and `toe` are not
  matcher tokens; rigs using only those names get -1 for the affected roles
  and must be mapped explicitly.

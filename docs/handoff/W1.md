## The failure

`ShapeFileTests.CorruptDefinitionIdReturnsCorruptData` and `ShapeFileTests.BadReferencesReturnInvalidTable` expected an error and got `None`.

Both remove a line from `shape-golden.sashape` with a pattern that ends in `\n`. The repository has no `.gitattributes`, so Git for Windows checked the fixture out with CRLF (`git ls-files --eol` showed `i/lf w/crlf`). The pattern matched nothing, the file stayed valid, and the parser correctly accepted it.

`families/humanoid-v1.safamily` was checked out with CRLF as well. Its tests pass either way, but it is a published data file, so its bytes should not depend on the platform that checked it out.

## The fix

`.gitattributes`:

```
*.sashape text eol=lf
*.safamily text eol=lf
```

After deleting and re-checking-out those four files, `git ls-files --eol` shows `i/lf w/lf`, and:

| Command | Result |
|---|---|
| `bash eng/dotnet_test.sh tests/SA.Shape.Tests/SA.Shape.Tests.csproj` | 73 of 73 on net10.0 and on netstandard2.1 |
| `bash eng/dotnet_test.sh tests/SA.Animation.Tests/SA.Animation.Tests.csproj` | 196 of 196 on both |

An existing Windows checkout keeps its CRLF copies until those files are checked out again: delete them and run `git checkout -- tests/SA.Shape.Tests/Fixtures families`.

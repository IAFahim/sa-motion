# N12 handoff: hinge axis and range inference from sampled motion

## What was built

`src/SA.Humanoid/Hinge/` (new, only files added by this packet):

- `HingeEstimate.cs`: readonly Sequential struct with the exact packet API
  (`Axis`, `Min`, `Max`, `Fit`, `Valid`), block-scoped `SA.Humanoid.Hinge`,
  C# 9.
- `HingeInference.cs`: `Estimate(rest, relativeSamples)` plus public threshold
  constants (`MinSamples = 3`, `MinMotion = 0.05`, `MinFit = 0.8`). Parent-frame
  deltas `sample * inverse(rest)` mapped to rotation vectors (sign-canonicalized,
  so `q`/`-q` mixes agree), 3x3 covariance accumulated in locals, dominant axis
  by fixed-32-step power iteration seeded from the largest diagonal, signed
  angles about the axis for `Min`/`Max`, aligned-energy share for `Fit`. Total:
  bad rest, fewer than 3 samples, any non-valid sample (non-finite or
  zero-length), zero energy, motion under 0.05 rad, or fit under 0.8 all yield
  `Valid` false with finite fields (axis falls back to +X, fit clamped to 0..1).
  No allocation beyond locals; the span is read twice, never stored.
  Simplest readings taken: minimum sample count 3 ("too few" is unspecified);
  any single corrupt sample invalidates the estimate; axis expressed in the
  parent frame via `sample * inverse(rest)`.

`tests/SA.Humanoid.Tests/Hinge/HingeInferenceTests.cs` (new, 17 facts): x/y/z
and oblique-axis hinge recovery (axis within 0.02 rad up to sign, range within
0.02 rad), ball motion low-fit invalid, sign-flip equality, determinism,
constant/single/empty/tiny-motion/NaN/Inf/zero-sample/bad-rest invalid with
finite fields, motion just over threshold valid.

`docs/hinge.md` (new): API, method, validity table, axis-sign and shortest-arc
notes, corrupt-sample policy. Touched nothing outside the packet paths.
`SA.Humanoid.csproj` and the test project are unchanged (SDK globs pick up the
new files).

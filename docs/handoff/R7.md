# Handoff R7: behavior coordination and locomotion drive

## What was built

`src/SA.ReactionControl/Coordination/*` only, plus `tests/SA.ReactionControl.Tests/Coordination/CoordinationTests.cs` and `docs/port/R7.md`:

- `ReactionMode.cs`: `Animated`, `Balancing`, `Bracing`, `Falling`, `Recovering` (byte enum).
- `CoordinationParams.cs`: named tuning fields replacing every readable `kv!` slot (`HysteresisMargin` 5, `FadeTime` 0.25 s, `MinLegStiffness` 50, `MaxLegStiffness` 600, stance/swing ankle/knee responses 3/2/1/2) with `Standard`. Values are authored, not measured.
- `Coordinator.cs`: `Arbitrate` maps the `behave` message-flag cascade and the `take_locomotion_drive` recovery gate onto data. Inputs are `ModeRequest` spans plus current mode and hysteresis margin; output is exactly one owner `ReactionMode` with an `ArbitrationReason` (`NoneActive`, `HighestPriority`, `HysteresisHold`, `Retained`). Priority ladder Falling 40, Bracing 30, Recovering 20, Balancing 10, Animated 0. Non-finite priorities never win, invalid modes are skipped, empty input falls back to `Animated`.
- `BlendWeights.cs`: per-role authority table 0..1 per mode (Falling fully passive), `Fade`/`FadePair` over the stated fade time with staying plus incoming equal to 1, `BlendAuthority`, and `BlendDrive` which lerps gains and nlerps normalized targets.
- `StanceDrive.cs`: `Resolve` replaces `actual_stance` plus the `valid` clamps (support equals wanted and contact, weight in 0..1, gain capped at weight, stiffness clamped to the authored band); `ResponseFor` picks the ankle/knee/hip muscle response by role and stance; `Calibrate` replaces `active_pose`/`incoming_pose` by converting an animation pose into a `JointDrive.Target` with zero target velocity and sanitized gains, so no output ever carries a position; `RelaxAuthority` adapts `body_relax` to a clamped `1 - relaxation` gain scale.
- Port record `docs/port/R7.md` was committed first and matches the code: slot map, 21-to-15 part collapse, excluded message framework and native force assembly, one ADAPTED entry each for arbitration, relax, and stabilise intent, unresolved `OpaqueContactMask`.
